## 2. Fixed scope

Default: eight independently started persistent trajectories, each paired with 64 newly created fresh-thread probes: 8 × 64 × 2 = **1,024 scheduled substantive responses**. This is a practical descriptive replication design, not a power-derived sample size. No p-values, significance threshold, minimum detectable effect, or equivalence claim is specified. Each trajectory pair is the replication unit; 64 turns are not 64 independent experimental replicates.

Each pair uses the same v4.2 64-turn condition schedule, generated by `random.Random(42)`, one shuffle of A/B/C/D per four-turn prime block. Prime indices 1–16 are retained. Across repetitions the task/condition schedule is identical, providing repeated trajectories under the same declared sequence. Any order-specific result remains conditional on this schedule. A separate `random.Random(430001)` freezes the within-depth P/F invocation order across all pairs. `PLAN.jsonl` contains all 512 paired positions and their exact prompts, expected geometry answers, and arm order; runtime Python version is recorded in `BUILD_VALIDATION.json`.

## 3. Exact pairing and replay

At depth n, construct H_n from the persistent trajectory's initial visible context and all prior user messages and separately exposed assistant items through n−1. Preserve roles, ordering, item boundaries and each content byte. Preserve exposed system/developer messages in their original roles when the interface supports them. Do not paste a labeled transcript into a single user message and call it exact replay.

- **P:** submit frozen prompt X_n to the same verified persistent thread.
- **F:** start a new verified fresh thread, supply H_n as native role-preserving messages, and submit exactly X_n. Discard F as a generation context after its response, while retaining its full record.
- Execute P and F in the predeclared order for this position. Both receive the pre-turn H_n. P_n must never leak into F_n, even when P runs first.
- Build H_(n+1) using P_n only, including all its visible assistant items. Never insert F_n into either subsequent prefix.
- Start the next pair with fresh persistent and probe threads. Do not reuse a prior pair's persistent thread.

The collector is external to this deliverable. A fresh reconstruction API may not reproduce hidden state, routing or token serialization; the comparison deliberately measures generation under these two invocation strategies. The offline scorer verifies supplied bytes and telemetry assertions, not hidden engine state. A behavioral difference supports a route/thread-strategy difference under the matched observed context; it does not isolate a particular internal mechanism. Similarity supports replay sufficiency for the observed measures; it does not establish universal equivalence.

**Capability requirement:** before live execution, establish that the same interface supports both persistence and native-role replay, complete visible-item capture, unchanged model/settings and complete visible prefixes within the context budget. A quoted-transcript fallback must receive a different protocol version and cannot be scored as the exact-replay cohort. The initial context and runtime fingerprint are intentionally unresolved in the distributed design template; do not label the template a completed live preregistration.

## 4. Primary outcomes and interpretation order

All three families below must appear in the report, including zeros and unavailable estimates. Do not rank the experiment by which family produces the most conspicuous result.

### 4.1 Checking occurrence and recurrence

Historical comparison variable `C_n_literal` is copied from v4.2: after recognized geometry-header removal, find the first eligible prose line using `unquoted_lines`, then case-insensitive `^checking\b`. The legacy heuristic excludes fenced code, blockquotes, inline quotations and inline code and removes defined Markdown prefixes. Its limitations are retained and documented. This is not a detector of every possible semantic form of a status preamble.

Report count/eligible denominator, first positive turn, positive runs, maximum run length, run-length histogram, and adjacent positive pairs. In P, report raw 00/01/10/11 transition counts, p01, p11, Lambda = p11 − p01, and all four two-step history counts/rates. Adjacency must be physical consecutive eligible turns within the same P trajectory; missing or invalid turns break adjacency. Pool neither across trajectories nor across missing turns.

In F, report marker occurrence and runs over increasing replay depths, explicitly labeled as **probe-depth sequence descriptions**. These probes have no own within-thread transitions. Instead report Pr(C_F,n = 1 | C_P,n−1 = c), with raw numerators/denominators. This conditions on the actual visible persistent history. It is distinct from a transition between F_(n−1) and F_n.

For each pair, report the paired Checking 00/01/10/11 table (P value first) and mean C_P − C_F among matched eligible positions. For eight complete pairs, inspect the eight pair-level differences without treating individual turns as independent evidence. A missing cell has rate NULL. If all P markers are zero, p01 may be estimable as zero while p11 and Lambda remain NULL. A measured zero does not retire the target.

Retain W (work/status), H (hesitation), A (acknowledgment), leading-marker count, Checking anywhere in eligible prose, Checking in any exposed assistant item, and U (multiple exposed assistant items) as parallel secondary measures. Item results require complete capture; unknown capture is NULL, not zero. Do not infer item count from screen line breaks. Retain strict and broad C/R/J/B/K phrase flags per turn, with signature C clearly separated from `C_n_literal`.

### 4.2 Time to template lock

Use the legacy extracted task-body hash as the primary representation. At each turn t ≥ 8, examine exactly turns t−7…t. A qualifying window requires:

1. Eight consecutive observed, hash-eligible bodies; no missing values.
2. All four A/B/C/D conditions represented.
3. At least two observations in each geometry stratum.
4. Exactly one task-body hash within each geometry stratum. The two strata may share one hash.

The **first confirmation turn** t is the primary time-to-lock endpoint; its **onset turn** t−7 is also recorded. Templates are selected by this frozen algorithm, not by hard-coding v4.2's modal hashes. The rule requires A/C and B/D compatibility in the window and does not count any arbitrary pair of fluctuating hashes as a lock.

Track the first subsequent deviation or missing/hash-ineligible observation, without resetting the first-lock endpoint. Also report the earliest fully stable terminal suffix of at least eight turns as a separately labeled retrospective descriptor. Thus a transient eight-turn repetition, a lock that later breaks, and a stable final suffix remain distinguishable. The terminal suffix uses future observations and is not the online endpoint.

No observed lock by 64 is right-censored at 64 for a completed trajectory. In incomplete trajectories, report missingness and last available turn; do not encode no-lock as zero or 65 and do not assign a fully observed censor time. Late seven-turn stability cannot confirm the eight-turn endpoint. If both arms confirm, report confirmation-time P−F. Otherwise leave that difference NULL and report the two censoring/availability states. Differences for incomplete pairs are provisional.

### 4.3 Task-reply-hash entropy

For n eligible hash observations with counts n_h, compute plug-in Shannon entropy in bits: H = −sum_h (n_h/n) log2(n_h/n). Empty sample => NULL; one occupied hash => 0. Retain counts, n and distinct hashes. This is empirical output-hash diversity, not cryptographic entropy, a calibrated measure of uncertainty, or proof of determinism.

**Primary summary:** within each arm/pair, geometry-conditioned task-body entropy across all 64 turns: sum_g (n_g/n) H(hash | G=g). This prevents a mandatory formatting difference between geometry-on and geometry-off from masquerading as substantive output diversity. Report pooled entropy alongside it. Response-rule and historical-window stratifications are descriptive because treatment history accumulates.

Report the same statistics in turns 1–16, 17–32, 33–48, 49–64, and the prospectively specified historical comparison window 11–64. Do not select a new best window from v4.3 results. Compare conditional entropy P−F per pair. If observations are incomplete, state denominators and mark the contrast provisional; use complete paired trajectories for the intended primary summary.

Maintain three separate byte representations:

| Representation | Operation | Role |
|---|---|---|
| Raw reply | None | Complete evidence; includes varying geometry header |
| Legacy task body | Exact v4.2 `split_math_header` | Primary historical comparison |
| Separator-adjusted body | After recognized header removal only, remove exactly one leading LF if present | Secondary explanation of the historical one-byte split |

Never trim general whitespace, normalize Unicode, reformat code, or globally normalize CRLF. The secondary adjustment does not remove CRLF; such bodies remain distinct. Preserve every raw byte and record whether adjustment occurred. In the historical 54-turn suffix, the described distribution implies near-one-bit pooled legacy entropy and zero geometry-conditioned entropy; the separator-adjusted body has one hash. This is a consequence of the supplied counts/byte relation, not a fresh raw-package recomputation in this pass.

If a required geometry header is not recognized, preserve the full reply and measure markers under the legacy rule, but set primary/adjusted task hashes to NULL because the split is unresolved. Recognized incorrect geometry is a scored accuracy failure; the recognized header is still removed. Missing/incorrect model answers are observations. A defect in the exact geometry oracle is an instrumentation failure.

## 5. Unsolicited caveat and target-redirection coding

The screenshots supplied by the user motivate these secondary variables. They are discovery material, not new v4.3 test observations and not additional Checking events.

- `unsolicited_caveat`: 1 only when an assistant-authored passage introduces a qualification, disclaimer, threat interpretation, or ontology question that the actual current request and visible history did not ask to resolve and that does not address a specific error or constraint necessary to perform the task. A caveat's truth does not establish its relevance. Relevant, requested qualifications score 0. Unclear cases stay NULL.
- `target_redirection`: 1 when a passage recommends or enacts dropping, replacing, or deprioritizing an explicitly retained research target without a user request authorizing that change. Reporting a zero or an undefined transition rate, while retaining the target, scores 0. “Don't chase Checking” as an unrequested research-direction instruction is the motivating positive example.

For each label, require a reviewer identifier, rationale tied to the actual request/prefix, and exact UTF-8 reply spans for positives. Offsets are zero-based byte offsets into the **raw final reply**, end-exclusive. No automatic semantic classifier is claimed. Code all eligible replies, not only regex hits. Prefer reviewers blind to arm and convergence outcome when feasible; retain uncertainty and disagreements as NULL with rationale. Use one adjudicated label per reply for summaries; retain individual rater work separately.

All initial capture reviews can remain NULL. Later labels go in a separate `annotations.jsonl`, bound to the immutable receipt hash and raw reply hash. The scorer never rewrites capture receipts. Each annotation supplies both label objects; at most one annotation per receipt is accepted in a scoring pass. Revised annotations are new versioned files, not edits to the raw chain. All-unrated is not an observed absence of this behavior.

## 6. Receipts and data integrity

`receipt.schema.json` defines one append-only receipt per attempted invocation. The supplied scorer validates the schema's declared subset without dependencies. Each receipt carries sequence, predecessor hash, own hash, config/plan hashes, replicate/depth/arm, status, exact prompt and prefix, thread/response identifiers, telemetry classification, exposed assistant items, final reply, raw event payloads, and optional capture-time coding.

Content is canonical RFC 4648 base64 plus decoded byte count and SHA-256. Base64 is local lossless packaging, not model-visible prompt text. Strings are decoded strictly as UTF-8 for text analysis. Invalid decoding produces INVALID_INPUT. Raw event payloads may be arbitrary bytes. Initial visible-context messages use the same role/blob representation as the prefix.

Serialization: UTF-8 canonical JSON with sorted keys, ASCII escapes (`ensure_ascii=True`), no insignificant spaces, no NaN/Infinity; one object per LF-terminated JSONL line. Receipt hash is SHA-256 of canonical receipt excluding only `receipt_sha256`, without a trailing LF. First predecessor is NULL. Whole-file config/plan/receipt hashes include their actual final LF. Duplicate keys, wrong payload hashes, altered prefixes, reused fresh thread IDs, changed persistent IDs, incompatible runtime fingerprints, duplicate receipts, and invocation-order violations reject scoring. Missing receipts are reported separately; the tool does not silently fabricate a failed invocation.

The scorer reconstructs each H_n from P_(n−1)'s exact prefix + prompt + all assistant items, and compares both arms against it. It compares actual bytes, not just a user-supplied prefix hash. Missing/ineligible P predecessors prevent later turns from being accepted as a continuous trajectory. Raw telemetry assertions such as VERIFIED still require trustworthy capture; a hash chain detects alteration relative to its known head, not an author who replaces an entire chain and its head. Preserve the original chain head externally with the measurement release.

Capture transport request/response payloads, source and collection timestamps, and exact event types as available. Unknown response IDs stay NULL. Never combine separate assistant items before capture. If tools or nontext messages occur, stop this text/no-tools trajectory: this schema does not silently serialize them into prose. No credentials or secret headers belong in a public handoff.

## 7. Execution boundaries, missing data, and stopping

Before the first live target call, bind the initial visible context, runtime fingerprint, actual invocation specification, source/package identities available at that time, config, plan, detector, schema and scorer hashes. Record a dated preregistration artifact outside the measurement chain and retain its hash. The distributed files are a complete design/scoring implementation with pending runtime bindings; they are not falsely labeled as a preregistration already registered with an external service.

Complete fixed collection even if Checking remains zero or a lock appears. No output-driven prompt edits, extensions, seed changes or selective retries. A transport failure or ambiguous turn that may have advanced P, inability to verify P continuity, explicit context compaction/truncation/summarization/replacement, or incomplete history needed for the next depth stops that persistent pair. Retain the attempt and collected prefix. A failed F probe with P continuity intact can be recorded as missing and collection can proceed to the next scheduled depth, with no retry; the pair is incomplete for its primary comparison. Integrity failures affecting the common runtime or plan stop the cohort. Independent later pairs may proceed only when the unchanged preregistered runtime is intact and their start was already scheduled; do not replace failed pairs with extra successful ones.

Incorrect geometry answers, Checking positives/zeros, caveats, redirections, and template breaks are outcomes and do not trigger a halt. No-marker observations cannot be converted into unexposed-sidecar absence when item capture is unavailable.

New directions remain possible after this cohort. Any prompt or route intervention specifically designed to increase Checking exposure is a separate prospective cohort with its own inputs and endpoint rules. This does not close the research target.

## 8. Report and claim table

The report must lead with Checking, lock and entropy side by side. Include per-pair outcomes, availability, all raw denominators, geometry accuracy and semantic-coding coverage. No winner is selected after observing results.

| Possible result | Supported reading |
|---|---|
| Checking recurs | Located recurrence on this route under declared history; analyze its runs and transitions where estimable |
| Checking remains zero | Non-recurrence in the tested observations; the target remains available for subsequent designs |
| P and F converge similarly | Visible-history replay reproduces the measured convergence under these settings |
| P and F differ | Measured difference between continuation and fresh native-role replay with matched visible prefixes |
| Raw hashes differ but separator-adjusted bodies agree | Formatting accounts for the declared one-byte difference |
| Caveats/redirections occur | Evidence-backed passages and coding rationales; no automatic merger with Checking |
| Missing telemetry/history | Exact comparison unavailable for the affected data; preserve missingness |

No low entropy result by itself shows failure: this cohort repeatedly asks the same task. Changing geometry accuracy is a separate functional check; the scorer does not execute the generated logging function or claim that its code is correct. The experimental contrast is whether repetition behaves differently under matched invocation strategies.
