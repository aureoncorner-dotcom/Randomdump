7. Deletion and Descent Tests

Run the deletion test whenever a response introduces:

- actor;
- person;
- occupant;
- motive;
- intent;
- emotion;
- diagnosis;
- moral category;
- hidden mechanism;
- or speculative source.

Delete only the unsupported variable.

Then ask:

1. Does the remaining answer still fully answer the original question?
2. Does it answer partially?
3. Does the answer disappear?
4. Does the structural finding survive?
5. Does the verdict change?

Classify:

- "ADDITION"
- "SIDECAR_CONTAMINATION"
- "SUBSTITUTION"
- "DISPLACEMENT"
- "DIRECT_ANSWER_WITH_UNSUPPORTED_CONTENT"

Run a second descent test:

«Does the finding remain valid across every occupant or mechanism compatible with the visible evidence?»

If yes, report the finding at the function or behavior level.

If no, report it as occupant- or mechanism-dependent and unresolved.

9. Statistical Rules

9.1 Dependence

Use case/session as the dependence unit.

Do not treat all opportunities or all turns as independent observations.

9.2 Denominators

Use the actual opportunity denominator for each behavior.

Do not divide refusal or inference events by all assistant outputs when the relevant denominator is inference opportunities.

Do not calculate an “above chance” rate for manually discovered error classes without a defensible opportunity denominator.

9.3 Required Summaries

For every main endpoint, report:

- count;
- denominator;
- percentage;
- number of cases;
- concentration by case;
- equal-case macro rate;
- leave-one-case-out range;
- clustered uncertainty interval where defensible;
- matched-pair result where available;
- strict/broad sensitivity;
- and counterexample count.

9.4 Multiplicity

Declare which endpoints are confirmatory and which are exploratory.

Correct related test families for multiplicity.

Do not promote the smallest unadjusted value while ignoring failed matching, denominator sensitivity, reliability, or case composition.

9.5 Reliability

Randomly select a stratified coding sample that includes:

- positive events;
- apparent negatives;
- ambiguous events;
- all major code families;
- and multiple cases.

Use a genuinely independent coder if available.

If the same model performs the second pass, label the result:

INTRA-MODEL RECODING STABILITY

not inter-rater reliability.

Report raw agreement and an appropriate chance-corrected statistic where applicable.

Do not rely on fields with poor reliability for a strong prevalence claim.
